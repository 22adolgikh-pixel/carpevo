# Как писать описания понятий по Керимову (т. II, рус.)

Источник: `/tmp/claude-0/qmmi/book.txt` — текст электронной версии т. II («Азербайджанский ковёр», рус.-англ. изд. 1983; файл QMMI).
Страницы разделены символом `\f` (form feed). Индекс страницы в файле i (с нуля) ↔ печатный номер этой электронной версии = i+1
(он же стоит внизу страницы). В ссылках указывать **этот номер** строкой, напр. "88".
Читать только русский текст (английский резюме в конце книги не нужен). Сноски внизу страниц — тоже источник (номер страницы тот же).

Образец стиля и формата: `pilot_2026-10-05.json` в этой папке (Бута, Гёль, Голлу чичи). Писать так же.

## Правила
1. Только то, что есть в тексте. Ничего не добавлять от себя (никаких общих знаний о коврах). Если Керимов высказывает мнение —
   писать «по Керимову», «Керимов считает». Если он спорит с другими авторами — коротко назвать чужую версию и его возражение.
2. Русский язык, ясный и простой — для читателя, который не знает ни ковров, ни азербайджанского. Термины пояснять при первом
   упоминании в скобках (как в образце: «гол — рукав»). Азербайджанские названия — в русской транскрипции Керимова, в «кавычках».
3. Разделы (3–6 на понятие, только те, для которых есть материал), заголовки короткие:
   - для узора/элемента: «Что это», «Откуда название / форма», «Виды», «Где встречается», «Как менялся смысл»;
   - для ковра/композиции: «Что это» (группа, тип, где ткут, другие названия), «Как устроено поле», «Каймы», «Происхождение»
     (если есть), «Варианты» (если есть), «Техника» (размер, плотность, ворс, цвета фона — числа точно как в книге).
   Каждый раздел 2–5 предложений. Числа, даты, названия сёл — точно по тексту.
4. В каждом разделе — `pages`: список печатных номеров страниц, на которых это сказано.
5. Не пересказывать стихи целиком; можно одной фразой сказать, что Керимов приводит народные стихи как довод.
6. Ссылки на рисунки и таблицы книги («рис. 64», «табл. 9», «схема 8») сохранять в отдельном поле `figs` раздела (список строк),
   в тексте их не упоминать.
7. Если глава не соответствует понятию из списка (другое слово, перепутано) — не писать описание, а добавить запись в `_problems`.

## Формат файла
```json
{
  "_about": "...",
  "source": {"id": "kerimov_v2_ru_e", "short": "Керимов, т. II (рус., эл. версия)", "file": "Drive: scans/QMMI_LIBRARY_119992_21-07-2017.pdf"},
  "items": {
    "<concept_id>": {"status": "draft_ai", "chapter": "«ГЫМЫЛ»", "sections": [
      {"title": "Что это", "text": "...", "pages": ["143"], "figs": ["рис. 125", "табл. 9"]}
    ]}
  },
  "_problems": [{"concept_id": "...", "chapter": "...", "note": "..."}]
}
```
Файл должен быть валидным JSON (проверить: `python3 -m json.tool FILE > /dev/null`).
