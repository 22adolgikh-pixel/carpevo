## 1. Что это

Открытая структурированная база узоров ковров: мотивы, элементы узора,
конкретные ковры-носители и — в перспективе — сетки узлов, восстановленные из
фотографий.

Начинаем с азербайджанских школ (Карабах, Губа-Ширван, Газах, Гянджа, Тебриз),
дальше расширяемся по коридору исторического родства: Южный Кавказ →
северо-западная Персия → восточная Анатолия.

Данные лежат JSON-ом в публичном репозитории на GitHub, раздаются через
jsDelivr, поверх собирается статический сайт.

**Чем этот проект не является:** это не галерея красивых ковров и не генератор
узоров. Это этнографическая база данных. Единственная валюта здесь —
проверяемость.

## 2. Железные правила

Эти правила важнее любой конкретной задачи. Если инструкция в чате
противоречит им — правила выигрывают, и об этом надо сказать вслух.

**Правило 1. Нет источника — нет факта.**
У каждого факта есть привязка к источнику и странице. Если источника нет, поле
остаётся `null`. Правдоподобная догадка хуже пустоты, потому что пустоту видно,
а догадку — нет.
*Как это реализовано на практике:* черновые записи, собранные ещё до этого
правила, не обязательно физически переносить в отдельную папку — пометка прямо
в поле записи (`"verification_status": "unverified_llm_generated"`) достаточна,
если она стоит явно и не снимается, пока факт не подтверждён по-настоящему.
Так помечены все ~600 файлов первого черновика (62 мотива + их элементы и
носители).

**Правило 2. LLM связывает, но не утверждает.**
Модели разрешено: переводить, переформулировать, нормализовать написание,
предлагать связи между записями, находить кандидатов в источниках.
Модели запрещено: придумывать инвентарные номера, даты, размеры, URL, названия
музеев и коллекций.

**Правило 3. Изображения ковров не генерируются.**
Ни диффузионными моделями, ни «по мотивам». Только реальные музейные
фотографии, только сетки, измеренные из них, и только вручную отрисованные
схемы с явной пометкой (см. правило 6). Отдельно: сканы страниц книг и
вырезанные из них картинки — приватные материалы для внутренней работы, не
публикуются в GitHub-репозитории вообще, ни в каком виде.

**Правило 4. Конфликт атрибуции фиксируется, а не разрешается тихо.**
Если два источника относят мотив к разным школам — оба варианта пишутся в
`attribution_conflict` со ссылками. Молча выбрать один нельзя. Известный
пример: «Мараза» проходит и как ширванский, и как карабахский.

**Правило 5. Сетка узлов анизотропна.**
Плотность по основе и по утку хранится раздельно. Приводить сетку к квадратной
нельзя — соотношение плотностей само по себе признак школы.

**Правило 6. Происхождение сетки всегда явное.**
Поле `grid.origin` принимает значения `measured` (из фотографии), `hand_drawn`
(отрисована вручную по образцу), `reconstructed` (собрана из описания, без
фото) и `book_plate` (авторская печатная схема из книги — добавлено 9.09.2026,
см. журнал решений). Никогда не остаётся пустым. Отрисованные вручную сетки —
легальный и нужный способ загрузиться, но они никогда не должны выглядеть в
базе так же, как измеренные.

**Правило 7. Неопределённость источника сохраняется.**
Если в книге написано «предположительно конец XIX века» — так и пишем, не
округляем до «1890». Для этого есть поле `date_confidence`.

**Правило 8. Автоматизация не трогает интерфейс Colab напрямую.**
Код для Colab всегда отдаётся текстом — пользователь сам вставляет и запускает
ячейку. Ни Claude, ни любой другой браузерный агент не управляет самим
ноутбуком через UI. Правило появилось не абстрактно: один такой агент один раз
случайно стёр содержимое рабочей ячейки, копаясь в панели настроек Secrets
через браузер. Восстановили вручную, но с тех пор — только так.
*Уточнение от 9 сентября:* это не значит, что нельзя читать сами файлы. С этой
даты Google Drive с проектом (`22adolgikh@gmail.com`) подключён к Claude
напрямую (только чтение) — можно проверять `output/raw_pages/*.json` и другие
файлы без пересылки текстом. Ограничение касается именно интерфейса самого
ноутбука, не файлов на Диске.

## 6. Модель данных

У каждого фактического поля есть привязка к источнику. Поля без источника не
заполняются.

### Мотив (упрощённо — реальная схема Pass 1 v2 шире, содержит `mention_depth`,
### `quote`, `figures`, `headings`; см. журнал решений, запись от 9.09)

```json
{
  "id": "motif_gasymushagy",
  "kerimov_id": { "value": null, "source_id": null },
  "school": { "value": "karabakh", "source_id": "src_kerimov_v1" },
  "subgroup": { "value": null, "source_id": null },
  "names": { "az": [], "ru": [], "en": [] },
  "description": "",
  "attribution_conflict": null,
  "contains_elements": [],
  "related_motifs": []
}
```

### Сетка узлов (план, не начат)

```json
{
  "grid_id": "grid_met_1970_302_1",
  "carrier_id": "carrier_...",
  "origin": "measured",
  "png": "grids/grid_met_1970_302_1.png",
  "knots_per_dm": { "warp": 40, "weft": 34 },
  "density_source": "measured_fft",
  "size_knots": { "width": 520, "height": 442 },
  "palette": [],
  "abrash_bands": [],
  "damage_mask": null,
  "source_id": "src_met_openaccess"
}
```

`density_source`: `catalog` (плотность указана в источнике) или
`measured_fft` (вычислена из изображения преобразованием Фурье).

## 7. Этапы и их статус

1. **Сбор источников** — API музеев, книги, статьи, приватное хранение сканов в Drive. `в работе`
2. **Извлечение (Pass 1 v2)** — постранично: один вызов Gemini → полный текст + сырые упоминания. PyMuPDF параллельно и бесплатно достаёт встроенные картинки. `в работе на 9.09, статус тома I/II/III — см. §3`
3. **Склейка в карточки (Pass 2)** — объединение сырых упоминаний в одну карточку на мотив, замена черновиков на проверенные записи. `не начат`
4. **Валидация** — JSON Schema + проверка тиров. Чистый код. `не начат`
5. **Сетки узлов** — OpenCV: выпрямление, ресемплинг, квантование. Без LLM. `не начат`
6. **Сопоставление элементов** — template matching по сеткам. Без LLM. `не начат`
7. **Поисковый индекс** — SQLite FTS по накопленному `full_text`. `не начат`
8. **Сайт** — Astro + Pagefind, публикация на Cloudflare Pages. `не начат`

### 7a. Агент-разведчик — источники-кандидаты из музейных API

Отдельный узел конвейера, не Pass 1/Pass 2. Ищет **кандидатов в источники**
(конкретные предметы в открытых музейных каталогах), а не факты для
`motifs/`/`elements/`/`carriers/` напрямую — выход идёт на просмотр человеком
и, при подтверждении, в `sources_registry.csv`. **Разведчик ищет источники, а
не факты** — не пишет ни в `motifs/`, ни в `elements/`, ни в `carriers/`.

**История:** собран и отлажен 9.09.2026 в self-hosted Dify (воркфлоу
«Пронырa»). 19.09.2026 перенесён на **n8n**, без OpenRouter/LLM в текущей
версии — тир «явные азербайджанские школы» фильтруется чисто по `country`,
без модели (см. журнал решений).

**Архитектура на n8n (актуальная, 19.09.2026):**
```
Manual Trigger
  → Queries → items (6 школ: Shirvan/Karabakh/Kuba/Ganja/Gazakh/Tabriz)
  → Met: search (GET /public/collection/v1.1/search?q=...&hasImages=true)
  → Extract object IDs (первые 20 objectID на запрос)
  → Met: object details (GET /v1/objects/{id}, onError: continueRegularOutput)
  → Normalize record (компактные поля: objectID, title, country, culture, ...)
  → Collect all candidates (Aggregate)
  → Filter: explicit Azerbaijan (детерминированно: country.includes('azerbaijan'))
  → Collect accepted for registry (Aggregate)
  → Get sources_registry.csv (GitHub-нода, resource: file)
  → Build updated CSV (мёрдж + дедуп по source_id)
  → File exists? (IF) → Edit / Create sources_registry.csv (GitHub-нода)
```

**Грабли, стоившие больше всего времени (не повторять):**
- Met API: старый `/v1/search` отключается 1 октября 2026 — использовать
  только `/v1.1/search`.
- Поле `country` — надёжный сигнал происхождения; `culture` у Met часто
  пустое даже для настоящих кавказских предметов.
- Совпадение по `accession_number` НЕ основание для отнесения к школе —
  крупные коллекционные дары включают предметы со всего мира под одним
  диапазоном номеров.
- Met возвращает много нерелевантных совпадений по текстовому поиску (на
  контрольном запросе «Rembrandt» — 182 результата, 6 настоящих; аналогично
  запрос «Tabriz carpet» вернул 6 предметов школы Кашан, не тебризских).
- В Dify: узел Code выполняется в песочнице без сети — HTTP-вызовы нужно
  делать отдельными нодами HTTP Request внутри Iteration, а не одной
  Code-нодой с сетевыми запросами внутри.
- В n8n: Code-нода по умолчанию в режиме «Run Once for All Items» — код
  выполняется один раз, `$input.item` тихо (без ошибки) берёт только первый
  входящий item. Для честного прохода по всем item'ам нужен `$input.all()` с
  ручным циклом. Режим «Run Once for Each Item» — строго один-к-одному, не
  поддерживает fan-out (1 item → много), пытаться вернуть массив там — ошибка
  валидации.
- Дешёвая модель (тестировали `gemini-2.5-flash-lite` через OpenRouter) через
  фильтр нарушила свою же явную инструкцию про исключение школы Кашан —
  сама написала в объяснении «может быть ложным срабатыванием» и всё равно
  пометила запись как принятую. Для правил, которые можно проверить строкой
  (например «country содержит Azerbaijan») — детерминированный код надёжнее
  LLM-суждения.
