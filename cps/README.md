# Carpet Pattern Studio v5

Запуск: двойной клик по `start.command` (или `pip install -r requirements.txt && uvicorn backend:app --port 8000`), затем http://localhost:8000

Сканы кладутся в `scans/` (или папку из `CPS_SCANS`, например Google Drive).

1. **Листы** — автопоиск рамок рисунков, правка, номер таблицы, **сложность** каждого рисунка (1 простой · 2 средний · 3 сложный · 4 ультра — клавиши 1–4 на выделенной рамке, выделение само идёт дальше) → «Сохранить и нарезать».
2. **Геометрия и сетка** — 4 угла (перспектива/поворот), контраст/яркость/гамма, авто-сетка, шаг/начало/кол-во клеток, тоны и пороги, превью.
3. **Пиксели** — инструменты иконками (подсказки при наведении), схема краёв матрицы (▲▼◀▶: зелёная — добавить ряд, красная — убрать, Shift — ×5), **пробел (удерживать) — подглядеть скан**; подписи и привязка к странице сайта, «✓ Готово → след.».
4. **Каталог** — все рисунки с фильтром по сложности, пакет JSON для сайта, легенда CSV, загрузка готовых рисунков.

На экранах 2–4 левой панели нет: рисунки листаются в шапке (‹ › или `[` `]`, ⏭ — следующий неготовый, выпадающий список — быстрый переход).

**⚡ Авто: сетка и пиксели** (`autogrid.py`). На экране «Листы» — кнопка «⚡ Авто: сетка и пиксели»: нарезает лист (если ещё не нарезан) и для каждого рисунка сам находит шаг сетки, наклон и углы, переводит клетки в пиксели и сохраняет как черновик (значок ⚡). Рисунки, где пиксели уже есть, не трогаются (Shift+клик — пересчитать все). На экране «Сетка» — кнопка «⚡ Авто» для одного рисунка. Дальше — проверка на «Пикселях» (пробел — подложка) и «✓ Готово → след.».
**По умолчанию — только тёмный контур** (флажок «+ заливка»/«+ серая заливка» включает старое поведение с серым тоном). Контур совпадает с ручной разметкой (45 рисунков, табл. 9–18, 63) на ~100 % (кроме табл. 13, где клетки рисунка не совпадают с миллиметровкой); серая заливка ~92 % — часто проще докрасить вручную, поэтому она теперь не включена по умолчанию.

## v8 (2026-09-29): цветные схемы и раппорт кайм
- **⚡ цвет** (`autocolor.py`). Переключатель «авто / ЧБ / цвет» рядом с кнопкой ⚡ (на листе и на рисунке). В режиме «авто» цветной рисунок распознаётся сам.
  - Шаг сетки ищется по границам цветных пятен (тест Рэлея), а не по линиям бумаги. Клетки бывают прямоугольными: в табл. 164 это 12.4×8.3 px. Узкие вертикальные каймы в книге напечатаны повёрнутыми, это учитывается.
  - На листе два прохода. Сначала каждый рисунок считается сам по себе, затем узкие полосы пересчитываются с шагом, найденным на уверенных рисунках листа.
  - Цвет клетки берётся как медиана Lab в центре клетки. Фон ищется отдельно, остальные цвета собираются k-means. Близкие оттенки сливаются, «рассыпанные» оттенки (шум печати) сливаются с соседним цветом.
  - Названия цветов подбираются по словарю красителей (az/ru, `DYES`). Фон — индекс 0.
  - Если авто разделило один цвет на два, задайте «цветов N» и нажмите «↻ цвета».
  - Если сетки нет (фото ковра, как табл. 204 «Джек»), пиксели не делаются, а рисунок помечается как фото.
- **Раппорт кайм** (`rapport.py`). Считается для полос (длина ≥ 1.9 ширины) или для рисунков, у которых в разделе стоит «кайма» / «бордюр». Пересчитывается при каждом сохранении пикселей.
  - Шаг повтора ищется по силуэту (весь рисунок или один цвет). Чистый фрагмент получается голосованием по повторам.
  - Клетки, расходящиеся с большинством, попадают в `suspect_cells`: это кандидаты в ошибки оцифровки.
  - Найденная симметрия записывается в `is_mirror` / `is_glide`.
  - Хранится в `work.rapport`; файл `_unit.png` — один повтор ×12. `POST /api/rapport/{id}` пересчитывает раппорт вручную.

## v10 — ускорение обработки массива
- **Вкладка «5 · Очередь»** (клавиша 5): авто-результаты, ещё не принятые человеком, мозаикой от надёжных к рискованным; порог риска,
  «выбрать надёжные», «✓ принять выбранные» (`POST /api/accept`). Пустой результат («рисунок не найден») получает риск 1.5 и не попадает в «надёжные».
- **Риск и симметрия** (`risk.py`): при автооцифровке ищется зеркальная/поворотная симметрия; если рисунок почти симметричен (≥90%),
  клетки, её нарушающие, подсвечиваются оранжевыми рамками в «Пикселях» (клик по «◇ симметрия» — скрыть). На 404 ЧБ-рисунках:
  среди подозрительных клеток доля реально исправленных человеком 12% против 0,8% в среднем (в ~15 раз выше случайного).
  Риск = 1 − уверенность + флаги + нарушения симметрии. `POST /api/risk_backfill` досчитывает для старых.
- **Ночной прогон** (`/api/prowl/start|stop`, `GET /api/prowl`): в фоне «Авто» на всех нарезанных, но не оцифрованных рисунках; прогресс в правой панели очереди.
- **Модель клеток ЧБ** (`learn.py`): нейросеть (numpy) на окне 5×5 нормированной яркости, учится на готовых рисунках.
  `docker exec deploy-cps-1 python learn.py eval|train`; сохраняется в `data/cell_model.json` только если в кросс-проверке по рисункам лучше порогов.

## v10.12 — согласие порогов и модели как сигнал надёжности
Идея: пороги (`classify`+`clean`) и обученная модель клеток — два независимых метода. Раньше модель включалась только при низкой уверенности порогов (подмена результата); теперь она считается **всегда** (если обучена), и результат сравнивается с порогами на каждом ЧБ-рисунке — независимо от того, какой из двух пошёл в итоговую матрицу. Полное совпадение — сильный сигнал «верно», заметное расхождение — сигнал «стоит проверить».
- Сигнал (`auto.agree`: доля расходящихся клеток среди закрашенных) добавлен в `risk.risk_score` — то есть сразу работает в существующей очереди и в кнопке «✓ принять N надёжных» (шаг 3 конвейера), без новых экранов.
- Проверка на 621 принятом ч/б рисунке (`cps-data`, пороги и модель прогнаны заново, сравнение с итоговой матрицей человека): в зоне «низкий риск» (≤0.25, где сейчас одной кнопкой принимают всё) доля рисунков с ошибкой >2% клеток упала с **27,7% до 11,8%** (220 рисунков вместо 397 — отбор строже, но то, что в нём остаётся, гораздо надёжнее: 26 бракованных из 220 вместо 110 из 397). Корреляция расхождения методов с реальной ошибкой: ρ=0,50 (для сравнения — мера искажения листа в v10.10 давала всего 0,09).
- Заодно сохраняется `work.auto_matrix` — сырой результат автомата этого прогона (до правок человека), отдельно от `work.matrix`, который дальше редактируют руками. Раньше это упоминалось как недостающий механизм (HANDOFF §7.2): нельзя было напрямую измерить ошибку автомата или дообучаться на разнице «автомат → правка человека», так как хранился только итог. Теперь можно — пригодится для будущих версий модели.
- Изменения только в `autogrid.py` (`auto_figure`, `to_work`) и `risk.py` (`risk_score`); `backend.py` не трогали — `/api/pipeline` и кнопка «✓ принять надёжных» подхватывают новый risk сами.
- Модель клеток нужно переобучить один раз после обновления (`learn.py train` или «обучить на готовых» в конвейере), чтобы `agree` считался для всех новых прогонов — она уже есть и обучена на 500 рисунках, менять её не нужно, только продолжать дообучать по мере роста готовых.

## v10.13 — «🎯 трудные места»: проверять куски, а не рисунки
Кнопка в очереди и в шаге 3 конвейера. Рисунок режется на куски 10×10 клеток; показываются только те, где пороги и модель клеток расходятся (`hard.py`), самые спорные первыми. Слева скан, выпрямленный по сетке, справа результат; спорные клетки обведены оранжевым, вокруг куска 3 клетки затемнённого контекста. Клик по клетке: фон → контур → серое (можно вести мышью, правый клик — фон); «A»/Enter — кусок верный, пробел — скан поверх результата, X — на доработку, → — следующий рисунок, E — открыть целиком.
- Когда все спорные куски рисунка проверены, рисунок принимается (`auto.accepted_via = "hard"`): остальное подтверждено согласием двух независимых методов. Рисунки без единого спорного куска принимаются сразу, без показа.
- **Проверенные куски сразу учат модель** (`learn.load_examples`): не принятый рисунок даёт примеры только из проверенных кусков (`hard.verified_mask`). Оценка качества модели по-прежнему только на принятых.
- Куски считаются при оцифровке и фоновым этапом «посчитать трудные места» (`/api/prowl/start {stages:["hard"]}`, 400 рисунков ≈ 10 с). Кэш в `work.hard` (`tiles`, `verified`, `sig`); если сетка или рамка матрицы меняются, кэш пересчитывается и отметки сбрасываются. API: `GET /api/hard/{id}`, `POST /api/hard/{id}/verify {tile:{x,y}, cells:[[x,y,v]]}`.
- Если спорных кусков больше 25 и они покрывают больше 70% рисунка, кусками дольше, чем целиком: экран предлагает «▦ сетка» / «✎ целиком».

Замеры (cps-data, 2026-10-04):
- На 574 принятых ч/б: спорных кусков медиана 7 на рисунок, в них 98% ошибок автомата; после проверки только их остаток >2 ошибочных клеток — у 7% рисунков. Показ только кусков с ≥3 расхождениями (медиана 4) — остаток у 18%, хуже.
- **В текущей очереди (402 непринятых ЧБ) выигрыш меньше**: спорных кусков медиана 24 (в очереди остались трудные рисунки); 123 рисунка попадают в «почти весь рисунок спорный», остальные 279 — в среднем ~19 кусков. Расхождения в основном про серое (≈70% клеток), разбросаны мелкими пятнами.
- Проверено и **отвергнуто**: автоматически решать «очевидные» споры (модель права в 98% там, где пороги теряют контур пятном ≥10 клеток) — кусков 24 → 22, не стоит усложнения; отбрасывать одиночные точки серого — кусков 24 → 20, но остаток ошибок вдвое больше.


## v10.14 — карточка «фото / схема» в «🎯 трудных местах»
Рисунки со слабой сеткой (`auto.grid_strength` < 2: сила линий `detect_grid`) в режиме 🎯 показываются не кусками, а одной карточкой со сканом: **📷 это фото (F)** — рисунок помечается `kind="photo"` и уходит из очереди схем; **▦ это схема (S)** — `auto.scheme_ok=true`, карточка больше не показывается, дальше обычные куски. - Порог 2 — по замеру на 1025 ЧБ-рисунках: среди принятых <2 у 1, в очереди — у 48. Из 12 просмотренных 8 — фото, 4 — настоящие схемы (узкая кайма, размытие), поэтому автоматически не переклассифицируем — решает человек одним кликом.


## v10.15 — свёрточная сеть клеток (`cnn.py`, веса `models/cnn_net.pt`)
Обучена в Colab (`tools/colab/cnn_colab.py`, 4000 шагов × 3 фолда по листам, аугментация). Замер на 839 принятых ЧБ рисунках с листов, которых сеть не видела (ошибка по закрашенным клеткам): пороги 22,5% → маленькая модель 16,8% → **сеть 9,0%**.
- `autogrid.auto_figure`: итог = сеть (`auto.engine="cnn"`); пороги и маленькая модель остаются вторым мнением. Нет `torch` или весов — всё работает как раньше.
- `hard.compute` для рисунков с `engine="cnn"`: спорно там, где с сетью не согласны пороги ИЛИ маленькая модель. Замер: медиана 10 кусков, 98% ошибок в них, остаток >2 клеток у 4,9% рисунков (было: пороги+MLP — 9 кусков, остаток у 8,0%). Варианты «спор только с порогами» (4 куска, остаток 13,3%) и «только с MLP» (9, 10,3%) хуже по остатку.
- Dockerfile ставит torch (только CPU, +~200 МБ). Время: ~0,6 с на рисунок.
- **Оговорка:** все замеры — на принятых (в основном лёгких) рисунках. В нынешней очереди (крупные заливки полутонами, засвеченные сканы) спорных кусков у сети почти столько же, сколько у порогов (медиана 30 из 39 на выборке из 25) — там нужен другой механизм (проверка областей, а не кусков).
- Перепрогнать очередь («↻ перепрогнать непроверенные» + «посчитать трудные места») — тогда рисунки получат результат сети.
