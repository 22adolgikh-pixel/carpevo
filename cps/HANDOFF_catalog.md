# Каталог ковров: конвейер отбора, углов и микрозадач (v11.30–v11.42, 2026-11-08…10)

Документ для того, кто продолжит работу. Подробности по версиям — в `cps/README.md` (разделы v11.30–v11.42), общая схема парсинга — `parse_plan_2026-10-29`.

## 1. Идея

Разбор ковров идёт по принципу «сначала грамматика, имена потом» (корни → выпрямление → полосы → повторы → названия). Ручной работы на 4000 фото слишком много, поэтому:

1. **Конвейер из ворот.** Этап за этапом машина делает предложение, человек правит только исключения; решённое попадает в обучающие примеры.
2. **Проверка пачкой и микрозадачи.** Один вопрос про один ковёр, ответ за секунды; можно делать с телефона и раздавать другим людям.
3. **Контрольный набор** (~20 полностью размеченных ковров, галочка «★») — мерило качества.
4. **Метрика — процент исправлений**, а не количество размеченного.

| Этап | Вопрос | Статус |
|---|---|---|
| 0. Что на фото | целый ковёр / обрезан кадром / фрагмент / не ковёр | машина (правила) + человек; обучение отложено (нужно ≈300 ответов) |
| 1. Углы | 4 угла ковра на фото | машина `find_quad` + человек (тянет угол) |
| 2. Выпрямление | ровный ковёр | автоматически (`rug_rect.rectify`) |
| 3. Поле / каймы | одна линия: где кончаются все каймы | **не сделан**: сначала шаг 1 в студии вручную, потом отбор кандидатов с обучением |
| 4. Слои кайм | стыки полос и их типы | **не сделан**: после этапа 3, 20–30 подтверждённых ковров |

## 3. Модель данных (в `data/rugs/<id>.json`)

- `auto` — предложение машины: `{frame, quad, conf, area, ver, t}`; `frame` ∈ whole / cropped / unsure.
- `frame` — решение: whole / cropped / fragment / not_rug; `frame_by` — `micro` (телефон) или `hand`.
- `tri` — путь решения по углам: `auto` (принято пачкой), `hand` (поправлено), `micro` (телефон), `review` (проверить вручную).
- `layout.quad_status`: `confirmed` (человек), `accepted` (принято пачкой без правки), прочее — как раньше.
- `micro` — голоса: `{frame|quad: {<user>: {a, w, t, q?}}}`.
- Отбор: `use_of(r)` в `rugs.py` → `work` (целый, фото ≥600 px, без людей, не фрагмент/двойник/разворот), `maybe` (обрезан, мелкое, не проверено), `skip` (причина в `use_why`). Керимов — всегда `work`; ковёр, связанный с Керимовым, в худшем случае `maybe`. Ничего не удаляется.

## 4. API

- `GET /api/rugs_triage` (очередь), `POST /api/rugs_triage` (расчёт пачки), `POST /api/rugs_triage_accept` (принять пачку: `ids`, `bad`, `quads`).
- `GET/POST /api/rugs_catalog` — фоновый проход (≈0,3 с на фото; сам стартует через 150 с после запуска).
- `GET /api/micro/next`, `POST /api/micro/answer`, `GET /api/micro/stats`; `GET /m`; `GET /rugmid/{id}.jpg` (1400 px).

## 5. Телефонный экран `/m`

- Карточки: «это целый ковёр?» (целый / обрезан / фрагмент / не ковёр / не знаю) и «рамка точно по краю?» (4 угла крупно с красным крестом; правка — двигать фото под крестом; два пальца — зум).
- Права: отвечать может любой вошедший, в том числе наблюдатель (`/api/micro/answer` в `VIEWER_OK`). Вес голоса: админ/редактор 2, остальные 1; решение применяется при весе ≥2. Два «поправил» применяются, если углы сходятся ≤2 % кадра (среднее).
- Контрольные карточки (~1 из 6): ковёр с углами, подтверждёнными вручную, верные или сдвинутые → точность человека (`/api/micro/stats`, шапка экрана).
- Очередь «целый ли ковёр»: половина сомнительных (низкая уверенность), половина случайных. Углы спрашиваются только у ковров с подтверждённым «целый».

- Машина просмотрела 3092 фото: cropped 1228, whole 945, unsure 919.
- Вывод: машинное «целый» ненадёжно, пока нет обученного классификатора.

## 6b. Ответы 2026-11-10 (≈300 карточек) и модель этапа 0

- «Целый ли ковёр» — 130 ответов: целый 73, обрезан 27, фрагмент 23, не ковёр 7. Машинное «обрезан» оказалось целым в 49 из 85: правило «ковёр касается края кадра» ловит плотно кадрированные магазинные фото, а не обрезанные ковры.
- Модель (`frame_model.py`, `models/frame_v1.json`): CV-точность 0,83; правило — 0,48. При пороге p≥0,6 среди отобранных 91 % целых. Важные признаки: уверенность `find_quad`, отступ углов от краёв кадра, площадь, перекос углов.
- На всём каталоге (3092 просмотренных) модель даёт p≥0,6 у 2187, 0,3–0,6 у 339, <0,3 у 566. Это распространение с перекошенной выборки (половина очереди была сомнительной) — проверять по случайной половине новых ответов.
- Углы — 118 ответов: «да» 7, «поправил» 78, «не то» 33. Медианная поправка 2,4 % кадра; машина ставит углы почти на край кадра (медианный отступ 0,2 % против 1,6 % у человека) и чуть выше/ниже по вертикали (бахрома на торцах). Улучшение `find_quad` требует самих фото — делать на сервере.
- Переобучение: выгрузить `data/rugs` (ветка `cps-data`) и запустить `tools/train_frame_model.py`; файл модели коммитится в репозиторий.

## 6a. Кривые и повреждённые края — решение

- Кривые края вручную не выравниваем (ни Безье, ни сетка): для выпрямления хватает 4 углов, а изгиб позже восстанавливается автоматически по повторам каймы — узор каймы служит линейкой.
- Утраты не дорисовываем: дорисовка стала бы данными, на которых учится машина. Утрата = «нет данных»; реконструкция по симметрии — позже, отдельным слоем «гипотеза».
- Утраченный угол ставится на пересечение продолжений уцелевших сторон, даже за краем ткани или кадра.
- Отмеченные ковры (`r.edge`) не идут в контрольный набор.

## 7. Эксплуатация

- Деплой: пуш в `cps-v5` → тесты (34, `python3 cps/tests/run_tests.py`) → SSH-деплой, ≈6 минут.
- Бэкап: ветка `cps-data` раз в ~3 минуты; с v11.42 в него входят `micro.jsonl` и `tri_log.jsonl`. Журналы до этой версии в бэкап не попали, голоса сохранены внутри ковров (`r.micro`).
- Токен бэкапа (`CPS_GITHUB_TOKEN`) меняет только владелец; прежний токен был раскрыт в терминале и должен быть отозван.
- Первый запуск прохода `catalog_run` после деплоя занимает 15–20 минут, ход виден над плиткой.
