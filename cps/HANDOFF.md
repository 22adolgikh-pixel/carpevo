## 1. Что за проект
«Ковровое ДНК» / CarpetsCat: оцифровка азербайджанских ковровых узоров из книги Керимова (том I, схемы на миллиметровке) в пиксельные матрицы + сайт «Ковровое ДНК» (термины, источники, носители). Инструмент оцифровки — **Carpet Pattern Studio (CPS)**: FastAPI `backend.py` + `index.html`. Дальше планируются: чтение узоров с фото ковров, подключение новых источников (журнал, книги), вкладка «Источники».

## 3. Архитектура CPS (кратко)
- Рабочий json на рисунок (`data/work/<id>.json`, id вида `t42_f05`): `sheet`, `table`, `fig`, `frame`, `quad` (4 угла в кропе), `grid{cols,rows,pw,ph,ox,oy}`, `matrix{w,h,origin,rows}` (строки base-36, `.`=пусто, `1`=контур, `2`=серое), `palette`, `palette_names`, `auto{confidence,flags,reviewed,edited,risk,symmetry,distortion,gray_restored}`, `rapport`, `done` (принят), `review` (на проверку), `color_mode`, `kind` (photo), `matrix_before_gray`.
- `autogrid.py`: `detect_grid` (поворот + единый шаг по линиям миллиметровки), `cell_means`, `classify`, `clean` (заливка серым по замкнутым областям: порог относительно бумаги + Оцу), `confidence`, `auto_figure(g, frame, dark_only=False, use_model=True)`.
- `learn.py`: MLP-модель клеток (`MODEL_GATE=0.6`), `final_centers(work)` — центры клеток по итоговым quad/grid, `matrix_labels(work)`.
- `rapport.py` (повтор каймы), `dupes.py` (ч/б ↔ цветные повторы), `autocolor.py` (цветные и фото), `distortion.py` (мера искажения), `lostgray.py` (возврат потерянного серого), `backup.py`/`restore.py`/`cloud.py`.
- Вкладки UI: «Конвейер» (5 шагов), «Листы», «Рисунки» (очередь+каталог); редактор (геометрия/пиксели) открывается поверх (Tab переключает); быстрая проверка; строка состояния внизу. Горячие клавиши: G — заливка, линия по умолчанию, ⌘' — пиксельная сетка, O/пробел — оригинал.
- API для сервисных задач: `/api/pipeline`, `/api/prowl`, `/api/prowl/start`, `/api/model/train`, `/api/broken?fix=1`, `/api/dupes`, `/api/lostgray?fix=1`, `/api/accept`, `/api/review_mark`, `/api/orig_aligned/<id>`.

## 4. Итоги разбора качества (v10.10–v10.11, на 621 принятом ч/б рисунке)
Скрипты: `cps/tools/analysis/` (README внутри).
- Ошибка автомата относительно итоговой матрицы: в среднем 4,7% клеток, медиана 0; 77% рисунков <5%; 17% рисунков дают 83% ошибки.
- **44 принятых рисунка (после проверки глазами) потеряли серую заливку**: старый прогон шёл с `dark_only=True`, рисунки принимали белыми. Без них ошибка 3,1%. Всего кандидатов в `/api/lostgray` на данных 3.10: 52 (часть спорна, поэтому они возвращаются в очередь, а не принимаются).
- Реальный остаток: ~30 из 483 рисунков с серым, где пропущено >50% серого (контур не замкнут); предсказать их по признакам нельзя (AUC 0,66).
- Автосетка по краям туши не хуже ручной: в 36 из 150 рисунков лучше, ручная лучше в 0 (шаг ручной на 2–8% больше шага бумаги). Расхождения «автосетка vs итог» в основном неточность ручной сетки.
- `quad_resid` пустая метрика (~1e-6). Добавлена `distortion.assess` (разброс/дрейф фазы линий бумаги по окнам): ставит `auto.distortion` и флаг «возможно искажение листа» (~5%), но связь с ошибкой слабая (rho 0,09).

## 6. Проверено и ОТВЕРГНУТО (не повторять)
1. Уточнение углов сетки по фазе линий бумаги в окнах (`distortion.refine`): шум окон ~0,2 клетки больше самой ошибки; сдвиг узлов 0,00 → 0,15; код удалён.
2. Закрытие разрывов контура (3×3, крест, линейное 1×3/3×1) перед поиском областей: на чистом эталоне лишнего серого 6,8% → 17–20%.
3. Классификатор замкнутых областей (GBM, яркость + площадь + текстура + листовые признаки): 90,5% против 89,9% у порога — нет выигрыша. Листы неоднородны по наличию серого (37 из 72 смешанные).
4. Все подборы заливки до v10.11 делались на «грязном» эталоне (с потерянным серым). Любые новые подборы делать через `tools/analysis/bench.py` (исключает `lost_gray`).
