## 2. Что есть на экране «3 · Ковры» (rugs.py, rug_layout.py, rug_match.py, блок JS в index.html)
**Данные.** Ковёр — `data/rugs/<id>.json` (паспорт: название, школа, тип/композиция, техника, музей, размеры…, `cat` — данные каталога, `same`/`same_ok` — двойники и подтверждения, `layout` — зоны, `marks` — элементы, `multi`/`split_into`/`split_from` — разделение разворотов). Фото `data/rug_img` (≤1600 px) или `data/rug_lib/img` (из каталога), миниатюры `data/rug_thumbs`. Рамка (`mark`): `box` в долях, `zone`, `motif` (словарь), `scheme` (id схемы студии), `group` (повторы одного элемента), `angle`/`flip` (положение схемы на ковре), `status` proposed/confirmed/rejected, `machine`/`score`/`xfer` (предложено машиной / перенесено с двойника), кто отметил и кто проверил. В бэкап входят `rugs`, `rug_img`, `rugs_settings.json`, `users.json`, `activity.jsonl`.

**Паспорт и каталог.** Школа по подписи/каталогу и предупреждение при расхождении источников; «этот же ковёр в других источниках» (двойники: ✓ тот же / ✗ другой); подтверждение «тот же» **дополняет пустые поля** паспорта у обеих карточек (школа, тип, техника, музей, инв., место, дата, размер), заполненные не трогает. Длинные подписи — в попапе «📄 текст источника». Фильтры: источник, школа, статус, «есть двойники», «✂ развороты».

**Разметка элементов.** Рамка мышью; зона (1–8); узор из словаря; схема студии; ожидаемые элементы по Керимову для выбранного типа ковра (клик или **перетаскивание** картинки на ковёр); повороты схемы ⟳/⇋ (Q/W); «＋ повтор», **автопоиск повторов** после каждой новой рамки (`rug_match.find_repeats`, повороты 0/90/180/270 и зеркало, сравнение яркости и контуров); «🔍 поискать эти элементы на фото» (`find_scheme`, масштаб — по уже отмеченному элементу со схемой; **грубее** поиска повторов); проверка предложений: ✓ все / только уверенные / убрать все / по одному (Tab, C, X); 🔗 «тот же узор, что…» (J), ✂ «отделить от повторов» (U), удаление рамки или всего элемента (после удаления выбирается следующая рамка группы). Схема накладывается на рамки выбранного элемента, растянутая по рамке, с оценкой искажения («узел на фото 4.6×3.8 px, сплющен на 16%»); фокус-затемнение (D), цвет по элементам или по зонам.

**Разделение разворотов.** `rug_match.find_carpets` → «✂ разделить фото» → отдельные карточки (исходная скрывается, разделение отменяется).

**Зоны.** `rug_layout.detect`: край ковра по фону и границы каймы по смене цвета почти по всему кольцу (медиана по 32 участкам); только целые ворсовые ковры, на фрагментах и безворсовых плохо (в паспорте предупреждение).

**Перенос разметки между двойниками.** `rug_match.align` (SIFT+RANSAC) + `map_box`; кнопки «⇐ взять / ⇒ передать разметку» у двойника; показывает размер фото двойника и подсказывает, на каком размечать удобнее; перенесённые рамки — предложения.

**Многопользовательский вход** (cloud.py, v10.19): роли admin/editor/viewer, журнал действий, пользователи dolgikh, lika, guest1.

## 3. Известные ограничения и подводные камни
- Поиск повторов даёт много «похожих» на мелкие элементы (розетки); для них принимать только «уверенные». Крупные элементы находит хорошо (проверено на «Гаджигайыбе»).
- В поиске по схеме масштаб берётся по первой рамке со схемой; если рамка нарисована небрежно, масштаб и поиск искажаются.
- Фото низкого качества (Керимов, сканы) — размечать на двойнике с лучшим фото и переносить.
- Любой тяжёлый расчёт на сервере — только через `run_in_threadpool` (v10.25 исправил зависание: синхронный поиск блокировал все запросы, пропадали миниатюры).
- В группах дублей из каталога бывают ложные склейки (выставки в Шуше и т. п.) — решает человек (✓/✗).
- Каталог каждый раз пересобирается без перезаписи правок человека (поле сохраняется, если отличается от прежнего значения каталога).
- Пользователь видит интерфейс на 2000-пиксельных скриншотах; координаты на них можно переводить в рамки (мой тестовый приём: Playwright + `R.z/ox/oy`).

## 6. Предложенный подход к разметке частей ковра (поле/каймы) — не реализован, обсудить с пользователем
1. Человек ставит 4 угла ковра (или подтверждает найденные) → фото выпрямляется (перспектива).
2. На выпрямленном ковре границы ищутся по профилю, сложенному с четырёх сторон (каймы симметричны: левая+правая, верх+низ), — один профиль вместо 32 участков, шум гасится.
3. Правка одной линии двигает её на всех четырёх сторонах (симметрия), отдельно — только если ковёр неровный.
4. Подсказка из двойника: зоны переносятся по совмещению (как рамки), из Керимова — число кайм по типу ковра.
5. Подтверждённые зоны (100+) — обучающий набор для модели.
